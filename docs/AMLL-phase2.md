# AMLL 第二阶段接入

第二阶段在第一阶段的逐字歌词基础上接入音译、对唱对齐、背景人声和多行同时激活，并继续使用 Melodia 原有的缩放、模糊、滚动与逐字高亮动画。

## 数据模型与解析

- `LyricLine` 新增 `romanization`、`alignment` 和 `backgroundLine`。背景人声仍是完整的 `LyricLine`，可拥有独立时间、逐字时间、翻译和音译。
- `TtmlLyricParser` 解析 `ttm:agent`、`x-translation`、`x-roman`、`x-bg` 以及 iTunes 外置翻译和音译。首个歌手映射到左侧，后续歌手映射到右侧。
- 背景人声从主歌词文本中分离，保留其绝对起止时间和逐字信息，不会重复混入主句。
- `LyricResolver` 在清洗异常数据时递归处理背景人声，同时保留第二阶段元数据。

## 播放状态与界面

- `PlayerViewModel` 暴露 `activeLyricIndices: Set<Int>` 和稳定的 `primaryLyricIndex`。所有时间区间覆盖当前进度的歌词都会同时激活；滚动锚点在重叠期间保持稳定，避免列表来回跳动。
- 行歌词沿用下一行开始时间作为有效结束时间；逐字歌词按自身区间判断。背景人声按自己的区间参与父行激活并独立推进逐字高亮。
- 全屏歌词和播放器歌词卡片显示左右对唱、翻译、音译和背景人声。背景人声使用较小字号和较低透明度区分。
- 悬浮桌面歌词仍只显示稳定主行的主文本，保持原有简洁行为。

- `:app:testDebugUnitTest` 全部通过，共 174 项 JVM 单元测试。
- `:app:assembleDebug` 构建成功。

- 真机播放器手工检查确认全屏歌词显示主歌词、翻译、背景人声及背景翻译。截图见 `docs/validation/device-phase2-lyrics.png`。

新增测试覆盖对唱歌手映射、内嵌和外置音译、背景人声独立时间与逐字信息、重叠主唱/对唱/背景人声同时激活、稳定滚动锚点以及行歌词的有效时间区间。

后续真机回归发现部分 AMLL 文件在一分钟前使用无单位秒值（如 `3.712`），一分钟后使用时钟格式（如 `1:02.962`）。解析器现已支持这种 TTML 混合时间格式，避免一分钟前的歌词被过滤。

全屏歌词为 115% 激活缩放预留布局宽度，并按左右对唱方向固定缩放锚点；长句会在安全宽度内换行，不再因激活动画越过屏幕边缘。
